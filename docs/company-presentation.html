MANAGEMENT DISCUSSION · 01

A shared brain.
A practical starting point.

THE TOOL / OUTPUT

Explore how reviewed AI assistance could connect work across Big Tiny, from finance to the guest experience.

FOR STAFF

Less time assembling context; more time acting on it.

FOR CUSTOMERS / PARTNERS

Clearer commitments and more dependable follow-through — hypotheses to test.

Data needed
Public company context and a working local proof of concept; no internal operating baseline.
Human decision
Discussion proposals only. Functional leaders choose which problems deserve a pilot.
Value test
Judge useful outcomes, not the number of agents.
Narration

This presentation explores how reviewed AI assistance could support Big Tiny across the business, from finance and sales to delivery and guest service. It is an opportunity discussion, not an approved roadmap. The aim is to reduce administrative effort and improve follow through. We should test those benefits before making commitments.

CURRENT CAPABILITY · 02

Working mechanism today.
Broader tools are proposals.

THE TOOL / OUTPUT

CURRENT: paste a note → extract facts → propose create, update or clarify → review → human approval → local task memory.

FOR STAFF

See a proposal and its evidence before changing saved work.

FOR CUSTOMERS / PARTNERS

No customer-facing actions are currently performed.

Data needed
One pasted note and saved tasks. Three prompts use the same on-prem model.
Human decision
Notes and agent outputs persist before approval. Only task mutations wait for approval.
Value test
Real fictional-example tests passed; staff productivity is not yet measured.
Narration

The working proof of concept accepts a note, proposes task changes or questions, reviews the result, and waits for a person to approve. It remembers local tasks. Notes and agent outputs are saved before approval; task changes are not. Everything else in this presentation, including source connections and departmental tools, is a proposed extension.

Start with evidence.
Keep decisions with people.

THE TOOL / OUTPUT

Authorised sources → bounded planning and lookup → draft → review → human decision → restricted action, only if approved.

FOR STAFF

Cited drafts and visible gaps rather than unsupported certainty.

FOR CUSTOMERS / PARTNERS

Commitments remain accountable and checked.

Data needed
Optional read-only documents and records, with source identity, permissions and freshness.
Human decision
No automatic cloud fallback. No autonomous payments, refunds, hiring or professional sign-off.
Value test
Source coverage, correction burden and permission failures.
Narration

A future shared service would need authentication, permissions and reliable records. Begin with read only information and cited drafts. Add planning, lookup or review roles only when they help the chosen workflow. Human approval must precede external writes or sends. There is no automatic cloud fallback, and the model cannot replace professional sign off.

Agree the problem.
Name the owner. Test the value.

THE TOOL / OUTPUT

FOR STAFF

FOR CUSTOMERS / PARTNERS

Keep guest, owner and partner outcomes visible in each decision.

Data needed
Confirmed data access, a baseline, success measures and critical-error stop rules.
Human decision
This is a discovery decision, not a company-wide implementation commitment.
Value test
Proceed, revise or stop based on measured evidence.
Narration

The management decision is to select one workflow worth testing, name its owner, and agree authorised sample data, a baseline and a pilot review date. Keep the current system authoritative while evaluating. Compare against the manual process and a simpler alternative. If the evidence supports improvement, extend one workflow at a time. Otherwise revise or stop. Let useful outcomes guide the next step.
